# توثيق كائنات النظام والهيكلية العامة (System Objects & Structure Documentation)

يوضح هذا المستند الهيكلية العامة لاستجابات الـ API، وتفاصيل الكائنات الرئيسية (User, Token, OTP, Country, City)، بالإضافة إلى شرح الـ Enums المستخدمة في النظام.

## 1. الهيكلية العامة للاستجابة (General Response Structure)

تتبع جميع نقاط النهاية (Endpoints) في النظام هيكلية موحدة للاستجابة (Wrapper)، مما يسهل على الواجهات الأمامية (Frontend) معالجة البيانات والأخطاء.

### نموذج الاستجابة الناجحة (Success Response)

```json
{
    "statusCode": 200,          // رمز الحالة (HTTP Status Code)
    "message": "Operation successful", // رسالة توضيحية للعملية
    "data": { ... },            // البيانات الفعلية (Object, Array, or null)
    "timestamp": "2023-10-27T10:00:00.000Z", // توقيت الاستجابة
    "path": "/api/v1/auth/login" // المسار الذي تم طلبه
}
```

### نموذج استجابة الخطأ (Error Response)

```json
{
    "statusCode": 400,          // رمز الخطأ (400, 401, 404, 500, ...)
    "message": "User already exists", // رسالة الخطأ
    "data": null,               // عادة ما تكون null في حالة الخطأ
    "timestamp": "2023-10-27T10:00:00.000Z",
    "path": "/api/v1/auth/register"
}
```

## 2. الـ Enums (القيم الثابتة)

### أ. أدوار المستخدمين (`UserRole`)

يحدد هذا الـ Enum صلاحيات ونوع المستخدم في النظام.

| القيمة (Value) | الوصف (Description) |
| :--- | :--- |
| `CUSTOMER` | **العميل**: المستخدم العادي الذي يقوم بطلب الطعام وتصفح المطاعم. (مسموح بالتسجيل العام) |
| `DELIVERY` | **السائق**: المستخدم المسؤول عن توصيل الطلبات. (التسجيل يتم عبر الإدارة فقط) |
| `MERCHANT` | **التاجر**: صاحب المطعم الذي يدير القوائم والطلبات الخاصة بمطعمه. (مسموح بالتسجيل العام) |
| `ADMIN` | **المدير**: لديه صلاحيات كاملة لإدارة النظام. (غير مسموح بالتسجيل العام) |

### ب. قنوات الإشعارات (`NotificationChannel`)

يحدد طريقة استلام رمز التحقق (OTP) والإشعارات الأخرى.

| القيمة (Value) | الوصف (Description) |
| :--- | :--- |
| `EMAIL` | يتم إرسال رمز التحقق والإشعارات عبر البريد الإلكتروني. |
| `WHATSAPP` | يتم إرسال رمز التحقق والإشعارات عبر تطبيق واتساب (WhatsApp). |
| `FIREBASE` | يتم إرسال الإشعارات عبر Firebase Cloud Messaging (FCM). القناة الافتراضية للمستخدمين الجدد. |
| `SMS` | يتم إرسال رمز التحقق والإشعارات عبر رسائل SMS النصية. |

### ج. أنواع التصنيفات (`CategoryType`)

يحدد نوع التصنيف (مطبخ عام أو قسم منيو خاص بمطعم).

| القيمة (Value) | الوصف (Description) |
| :--- | :--- |
| `CUISINE` | **مطبخ**: تصنيف عام (مثل إيطالي، برجر) يربط عدة مطاعم ببعضها. يتم إدارته من قبل الإدارة. |
| `MENU` | **قائمة طعام**: قسم داخل منيو مطعم محدد (مثل مقبلات، مشروبات). يتم إدارته من قبل التاجر. |

## 3. تفاصيل الكائنات (Objects Detail)

### أ. كائن المستخدم (`User Object`)

يمثل المستخدم في النظام بجميع أدواره.

```json
{
    "id": 1,                        // المعرف الفريد للمستخدم
    "firstName": "Test",            // الاسم الأول
    "lastName": "User",             // الاسم الأخير
    "email": "customer@example.com",// البريد الإلكتروني (يجب أن يكون فريداً)
    "phone": "+963912345678",       // رقم الهاتف
    "role": "CUSTOMER",             // الدور (من UserRole enum)
    "notificationChannel": "EMAIL", // قناة الإشعارات المفضلة
    "address": "Damascus, Street 1",// العنوان النصي
    "isOnline": false,              // (للسائقين فقط) حالة الاتصال
    "verifiedAt": "2023-10-27T10:00:00.000Z", // تاريخ التحقق من الحساب (null إذا لم يتم التحقق)
    "currentLat": null,             // (للسائقين فقط) خط العرض الحالي
    "currentLng": null,             // (للسائقين فقط) خط الطول الحالي
    
    // العلاقات (Relations)
    "countryId": 1,                 // معرف الدولة
    "country": { ... },             // كائن الدولة (انظر تفاصيل Country)
    
    "cityId": 1,                    // معرف المدينة
    "city": { ... },                // كائن المدينة (انظر تفاصيل City)
    
    "areaId": 1,                    // معرف المنطقة (اختياري)
    "area": { ... },                // كائن المنطقة (انظر تفاصيل Area)
    
    "createdAt": "...",             // تاريخ الإنشاء
    "updatedAt": "..."              // تاريخ آخر تعديل
}
```

### ب. كائن الرمز (`Token Object`)

يتم إرجاعه عند تسجيل الدخول الناجح لاستخدامه في المصادقة (JWT).

```json
{
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", // رمز الوصول (JWT)
    "user": { ... } // كائن المستخدم الكامل (كما هو موضح أعلاه)
}
```

* **ملاحظة**: يجب إرسال هذا الرمز في الـ Header للطلبات المحمية: `Authorization: Bearer <access_token>`.

### ج. كائن الـ OTP (آلية العمل)

الـ OTP (One-Time Password) ليس كائناً يتم تخزينه بشكل دائم في قاعدة البيانات بنفس مفهوم المستخدم، بل هو قيمة مؤقتة يتم التعامل معها كالتالي:

1. **التوليد**: يتم توليد رقم عشوائي (مثلاً 6 أرقام).
2. **التخزين**: يتم تخزينه في ذاكرة مؤقتة سريعة (Redis) مع مفتاح مرتبط بالمستخدم (إيميل أو هاتف) وفترة صلاحية (TTL) قصيرة (مثلاً 5 دقائق).
3. **الإرسال**: يتم إرساله عبر `NotificationChannel` (إيميل أو واتساب).
4. **التحقق**: عند إرسال المستخدم للكود، يتم مطابقته مع القيمة المخزنة في Redis.

**الاستجابة عند طلب OTP (تسجيل أو نسيان كلمة مرور):**

```json
{
    "message": "User registered successfully. Please verify your account using the OTP sent to your email.",
    "userId": 1
}
```

### د. كائن الدولة (`Country Object`)

يمثل الدولة التي يعمل فيها النظام.

```json
{
    "id": 1,
    "name": {
        "ar": "سوريا",      // الاسم بالعربية
        "en": "Syria"      // الاسم بالإنجليزية
    },
    "code": "SY",          // رمز الدولة (ISO Code)
    "callingCode": "+963", // رمز الاتصال الدولي
    "currencyCode": "SYP", // رمز العملة
    "currencySymbol": "£", // رمز العملة (الرمز التعبيري)
    "currencySmallestUnit": "Piastre", // أصغر وحدة عملة
    "currencyFactor": 100, // معامل التحويل (1 ليرة = 100 قرش)
    "isActive": true       // هل الدولة مفعلة في النظام
}
```

### هـ. كائن المدينة (`City Object`)

يمثل المدينة التابعة لدولة معينة.

```json
{
    "id": 1,
    "name": {
        "ar": "دمشق",
        "en": "Damascus"
    },
    "countryId": 1,        // معرف الدولة التابعة لها
    "country": { ... }     // كائن الدولة المرتبط (اختياري حسب الطلب)
}
```

### و. كائن التصنيف (`Category Object`)

يمثل تصنيفاً للمطاعم (Cuisine) أو للمنتجات (Menu Section).

```json
{
    "id": 1,
    "name": {
        "ar": "إيطالي",
        "en": "Italian"
    },
    "type": "CUISINE",     // نوع التصنيف (من CategoryType enum)
    "restaurantId": null,  // معرف المطعم (إذا كان النوع MENU)
    "imageUrl": "...",     // رابط الصورة
    "displayOrder": 1,     // ترتيب العرض
    "isActive": true       // حالة التفعيل
}
```

## ملخص سير العمليات (Workflow Summary)

1. **التسجيل (Register)**: ينشئ المستخدم (CUSTOMER أو MERCHANT) حساباً ويختار `notificationChannel`. النظام يرسل OTP.
2. **التحقق (Verify)**: يرسل المستخدم الـ OTP لتفعيل الحساب (`verifiedAt` يصبح تاريخاً بدلاً من `null`).
3. **تسجيل الدخول (Login)**: يحصل المستخدم على `access_token` وكائن `user` كامل.
4. **تصفح البيانات**: يستخدم `access_token` لجلب المدن، المطاعم، إلخ.
