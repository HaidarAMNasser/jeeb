# 📚 المكاتب والتقنيات المستخدمة (Libraries & Tech Stack)

يوضح هذا الملف قائمة المكاتب والتقنيات المستخدمة في مشروع **Jeeb**، مع شرح سبب اختيار كل مكتبة ودورها في النظام.

---

## 1️⃣ الإطار الأساسي (Core Framework)

| المكتبة | الإصدار | الوصف وسبب الاختيار |
| :--- | :--- | :--- |
| **@nestjs/core** | Latest | إطار العمل الأساسي. تم اختياره لبنيته القوية (Modular Architecture) ودعمه الممتاز لـ TypeScript. |
| **@nestjs/common** | Latest | أدوات NestJS الشائعة (Decorators, Modules, etc). |
| **@nestjs/platform-express** | Latest | منصة HTTP الأساسية المستخدمة لتشغيل الخادم، مبنية على Express.js. |
| **rxjs** | Latest | مكتبة التعامل مع الأحداث غير المتزامنة (Reactive Programming)، أساسية في NestJS. |
| **reflect-metadata** | Latest | ضرورية لعمل الـ Decorators في TypeScript و NestJS. |

| المكتبة | الوصف |
| :--- | :--- |

## 4️⃣ المجدولات والمهام الخلفية (Schedulers & Background Jobs)

هذا الجزء حيوي لأتمتة المهام التي لا تتطلب تدخل المستخدم أو تحتاج للتنفيذ بشكل دوري.

| المكتبة | الوصف ودورها في النظام |
| :--- | :--- |
| **@nestjs/schedule** | **إدارة المهام المجدولة (Cron Jobs)**. تُستخدم لتنفيذ مهام دورية في أوقات محددة. **مثال في النظام:** تنظيف سجلات الإشعارات والـ OTPs القديمة يومياً في منتصف الليل (`NotificationsService`). |
| **bullmq** | **إدارة طوابير المهام (Job Queues)**. تُستخدم للمهام الثقيلة التي يجب أن تعمل في الخلفية دون تعطيل استجابة الخادم (Asynchronous Processing). **الاستخدامات:** معالجة الطلبات، إرسال الإشعارات الجماعية، التسويات المالية. تعتمد على Redis. |
| **@nestjs/bullmq** | وحدة الدمج الرسمية لـ BullMQ مع NestJS، توفر طرق سهلة لإدارة الطوابير عبر الـ Decorators. |
| **ioredis** | عميل Redis القوي، يستخدمه BullMQ لإدارة الطوابير ولتخزين البيانات المؤقتة (Caching). |

## 6️⃣ إدارة الإعدادات والتحقق (Configuration & Validation)

| المكتبة | الوصف |
| :--- | :--- |
| **@nestjs/config** | لقراءة متغيرات البيئة (`.env`) بشكل آمن ومنظم داخل التطبيق. |
| **class-validator** | للتحقق من صحة البيانات المدخلة (Validation) في الـ DTOs (مثل التأكد من أن البريد الإلكتروني صالح). |
| **class-transformer** | لتحويل البيانات (Serialization) بين الـ Objects والـ JSON (مثل إخفاء كلمة المرور عند إرجاع بيانات المستخدم). |
| **@nestjs/mapped-types** | لإنشاء أنواع DTOs جزئية (Partial Types) بسهولة (مثل `UpdateDto` من `CreateDto`). |
